# QA cleanup

1. Before running, record exact ownership and a teardown action for each resource: session, tab, process, recorder, port, profile, temp path, fixture, or external test object. Keep scratch separate from deliverable evidence. Use isolated data; do not make a persistent or shared mutation without authorization and a way to undo it.
2. Whenever an attempt ends, including on failure, cancellation where possible, or a retry, finalize owned recorders first. Inspect and separate the evidence needed for delivery. Close only owned sessions and processes, and restore authorized test mutations or remove fixtures by exact ID. Order these actions so a live process cannot recreate the state you removed. Verify resources are gone and state is restored. Do not stop shared services, close attached personal apps, or run broad cleanup commands.
3. Show the reviewed results before discarding their remaining scratch copies. Remove owned scratch, failed captures, and render intermediates once no longer needed. Verify the delivered files still open at the paths you report. Keep only the evidence promised to the user; do not delete a linked file without an agreed retention policy or explicit request. If evidence is embedded or copied to an approved durable destination, confirm it is accessible before deleting the local delivery copy.
4. Report any leftover resource, mutation, or evidence that could not be cleaned up safely, why, and what would resolve it. Cleanup failure does not erase the observed result, but the QA run is not complete while required teardown is unresolved.
