# Adopt e2e QA

Make the project's `install-qa` output drive apps through `e2e-qa`. Every step is safe to rerun. `/install-qa` regenerates its files on each run and puts droid-control back, so rerun this skill after it.

The rewire script is `${DROID_PLUGIN_ROOT}/skills/adopt-e2e-qa/scripts/rewire.py`. Run it from the repository root with Python 3.

## 1. Make sure the QA skills exist

Run the script with `--check`. Exit 3 means the project has no `install-qa` output. Load Droid's built-in `install-qa` with `Skill` and complete it first. During its questionnaire, answer no to Droid Control Compose. Its droid-control setup is undone in step 3.

## 2. Map apps and flows

Write `.factory/skills/qa/e2e.yaml` in the shape of [references/e2e-yaml-example.md](references/e2e-yaml-example.md). Keep existing entries that still resolve.

1. **Driver per app.** For each app under `apps` in `config.yaml`: `e2e` for web, iOS, Android, and native macOS; `tuistory` for CLI and TUI; `agent-browser` for an Electron renderer or the Factory browser pane; `curl` for an API.
2. **e2e setup.** For each `e2e` app, find the project's e2e config and target, or set them up through [agent-owned setup](../e2e-qa/references/setup.md). Run `npx --no e2e doctor --target <target>` and resolve its findings.
3. **Flows.** List every flow label in each `qa-<app>` skill's flow menu. Map a label to an e2e test (`file` or `file:line`) only when that test drives the flow and asserts its success criteria. Otherwise map it to `null`, which means e2e-qa drives it live. Never map a test because its name looks similar.

## 3. Rewire

1. Run the script without flags. It adds the managed `e2e-qa` block to `qa` and every `qa-<app>` skill, removes droid-control and its marketplace from `.factory/settings.json`, sets `droid_control.compose` to false, and adds `interaction_layer: e2e-qa` to `config.yaml`. It never touches `e2e.yaml`.
2. Run `droid plugin list --scope project`. If droid-control is installed there, run `droid plugin uninstall droid-control@factory-plugins --scope project`.
3. For each CI file the script lists, edit only the QA job:
   - Replace droid-control wording in the agent prompt with "use e2e-qa for every interactive flow".
   - Replace driver installs with what the [QA integration CI section](../e2e-qa/references/qa-integration.md#ci) lists. Remove `agg`, Remotion, and Compose steps.
   - Leave triggers, secrets, report posting, artifacts, and every other job unchanged.
4. Run the script with `--check` until it exits 0.

## 4. Prove one flow

Load `e2e-qa` and run one mapped flow for one persona through its QA integration guide, with `RUN_ID=adopt-<date>`, if a mapped flow exists. If any flow is unmapped, also drive one live through its selected driver. If all flows are unmapped (for example an API-only project), a live flow is the proof. Fix wrong mappings and rerun. Run the cleanup after every attempt and confirm the evidence still opens.

## Done when

- `rewire.py --check` exits 0.
- `e2e.yaml` has an entry for every app in `config.yaml` and every flow label in each `qa-<app>` skill, mapped or `null`.
- `droid plugin list --scope project` shows no droid-control.
- No CI file mentions droid-control.
- One mapped flow passed if mappings exist, one unmapped flow passed if any exist, evidence paths are linked, and cleanup was verified.
- The reply gives mapped and unmapped counts per app, the CI edits, a reminder to rerun after `/install-qa`, and points at `maintain-qa-skills` for upkeep.
