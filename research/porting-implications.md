# factory-stack: porting implications (pstack → Droid)

Based on `droid-harness.md` (sources accessed 2026-11-10). Each row names the Factory primitive that should replace a pstack concept. ⚠ marks a row that depends on an UNVERIFIED item there.

| pstack concept | Factory replacement | Notes / constraints |
|---|---|---|
| **Cursor Task subagents** | **Task tool → custom droids** in `.factory/droids/<name>.md` (or `droids/` in a plugin). Built-ins: `worker`, `explorer`. | `subagent_type` = droid `name` (`^[a-z0-9-_]+$`). The droid body is the system prompt. Subagents get no `AskUser` and no `Task`: **no nested fan-out**, so the orchestrator must be the main session. ⚠ v1.8.0 Task runs every call in the background and delivers reports automatically; the docs still describe foreground as the default. |
| `subagent_type` param | droid `name` / filename | One droid file per pstack role (e.g. `explorer`, `reviewer`, `verifier`). Mark a read-only role with `tools: read-only`, which is enforced (unlike skill `allowed-tools`). |
| `model` param on Task | droid frontmatter `model:` + `reasoningEffort:`, **or** `model: inherit` + Task `complexity: light|medium|heavy` routed by `subagentModelSettings` | Task has no per-call model override; the model comes from the droid file or the complexity tier. A pinned model that is disallowed falls back to the parent's. ⚠ Whether `complexity` is still a Task param in v1.8.0 is unverified. |
| **Parallel fan-out (swarm)** | Several `Task` calls in **one assistant message** (each background) → reports auto-delivered; `TaskOutput block=false` to peek, `TaskStop` to cancel. Alternative: `Script` tool with `Promise.allSettled` for tool-level fan-out. | For N workers editing the same repo, each worker must use a separate tree. In-session subagents share the cwd, so for edit-heavy swarms use headless `droid exec --worktree <name>` jobs instead. |
| **Arena (N candidates, pick and graft)** | N × `droid exec -w arena-<i> --auto medium -o json "<task>"` in parallel (each on its own worktree branch). Then a judge step: a main-session Task with a read-only `arena-judge` droid, or `droid exec` over the diffs. | Exec removes clean worktrees on exit but keeps dirty ones and prints their path. Branches are never deleted. Capture `session_id` from the json output to `-s` resume or `--fork` the winner. |
| **pstack-models (model-per-role rules)** | (a) Per-role `model`/`reasoningEffort` in each droid file; (b) `subagentModelSettings.{light,medium,heavy}{Model,ReasoningEffort}` in `.factory/settings.json`; (c) `missionModelSettings.*` + `missionOrchestratorModel` for Missions; (d) `-m/-r`, `--spec-model`, `--worker-model`, `--validator-model` flags for exec. | Prefer the **tier aliases** (`anthropic-latest-premium`, `openai-latest-balanced`, `claude-opus-*` …) over hard-coded IDs; model IDs churn and the doc examples are stale. A setup-pstack equivalent should write `subagentModelSettings` plus droid `model:` fields. |
| **Cloud agents** | **Missions** (`/missions`, `droid exec --mission --auto high`) for orchestrated multi-worker runs; **Workstreams** (beta, Factory App, Pro/Plus/Max/Teams) for multi-day, multi-PR work; **Environments / Droid Computers / Remote Control** for compute; **Automations** (`CreateAutomation`/`RunAutomation`) for scheduled or triggered runs. | ⚠ Programmatic session creation (`POST /api/v0/sessions`) is "enabled for selected organizations only". The portable baseline is local or CI `droid exec`. |
| **Slash-skills** (`/swarm`, `/arena`, …) | **Skills** in `.factory/skills/<name>/SKILL.md`: `user-invocable: true` (the default) gives `/name` automatically, usable anywhere in the prompt and several per prompt. Use `disable-model-invocation: true` for user-only workflows. | Required frontmatter: `name`, `description`. Supporting files are not auto-loaded and must be referenced from SKILL.md. Custom commands (`.factory/commands/*.md`, `$ARGUMENTS` only) are legacy; use them only as thin wrappers (`Load skills: **x**.`). A same-named command shadows the skill's slash. |
| **AGENTS.md / rules** | `AGENTS.md` (root plus nested; also `.factory/AGENTS.md`; personal `~/.factory/AGENTS.md`) for always-on rules. Path-scoped rules → nested `AGENTS.md` (loaded when files in that tree are read, edited, listed or searched, but **not** on Execute). `DESIGN.md` for design guidance. | Budget: 80k characters at startup, 40k per dynamic load. pstack `principle-*` skills stay skills (on demand). Only the short always-on core goes in AGENTS.md. |
| **Hooks for enforcement** | `.factory/hooks.json` (or a plugin's `hooks/hooks.json`). `PreToolUse` with `permissionDecision: deny` or exit 2 to block; `PostToolUse` for format and lint feedback; `Stop`/`SubagentStop` with `decision:"block"` to force verification before finishing; `UserPromptSubmit`/`SessionStart` to inject context. Pair with `permissionRules` (block/ask/allow on shell prefixes, testable with `droid rules check`). | Use `"$FACTORY_PROJECT_DIR"` or `${DROID_PLUGIN_ROOT}` paths. ⚠ Whether PreToolUse fires for tool calls *inside* subagents is undocumented; enforce per-droid with the `tools:` allowlist as well. |
| **Headless verification runs** | `droid exec` (read-only by default; `--auto low|medium` as needed) with `-o json` (check `is_error` and `result`, keep `session_id`) or `-o stream-json` for tool-call audit. Use `--only-tools`/`--remove-tools` for least privilege, `--append-system-prompt-file` for the verifier rubric, and `--cwd`/`--worktree` for isolation. In CI: the install script plus `FACTORY_API_KEY` secret, or `Factory-AI/droid-action` for PR review. | Exit 0 ≠ success. Assert with deterministic checks afterwards. An `ask` permission rule makes exec fail rather than prompt. For multi-turn verifier loops use `--input-format stream-jsonrpc` or the TS/Python SDK. |
| **Packaging / distribution of pstack** | One **plugin** (`factory-stack/.factory-plugin/plugin.json` + `skills/ droids/ commands/ hooks/ mcp.json`) inside a **marketplace** repo (`.factory-plugin/marketplace.json`). Install with `droid plugin marketplace add <repo>` → `droid plugin install factory-stack@<mkt> --scope user|project`. | Teams auto-enable it via `extraKnownMarketplaces` + `enabledPlugins` in `.factory/settings.json`. Remember precedence: project skills beat plugin skills of the same name. |

## Design consequences to carry forward

1. **One-level orchestration.** Subagents cannot spawn subagents, so swarm and arena orchestrators must run in the main session or as an outer shell or `droid exec` driver.
2. **Isolation via worktrees.** In-session Task workers share the cwd. Parallel edit work should go through `droid exec --worktree` or Missions.
3. **Enforced vs advisory tools.** Droid `tools:` is enforced; skill `allowed-tools` is not. Put every hard boundary in droids, hooks or `permissionRules`.
4. **Model routing lives in config.** Task calls carry no model, so pstack-models becomes generated droid frontmatter plus `subagentModelSettings`.
5. **Verify unverifieds early.** Before building, run an authenticated smoke test covering:
   - Task background semantics and whether it accepts `complexity`/`run_in_background`;
   - hook firing inside subagents;
   - project droid and skill discovery in `droid exec`;
   - droid `reasoningEffort` values above `high`.
